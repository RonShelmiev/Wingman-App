# Changelog

Every push is documented here: what changed and why. Newest first.

## 2026-10-13 — Alarm sound + delivery diagnostics

**Fixed**
- Opening Wingman onto a waiting alarm showed it silently (browsers block sound until the first tap). The alarm screen now says "Tap anywhere to hear the alarm" and any tap starts the sound.
- On iPhone (iOS 17+), the alarm sound asks for "playback" audio, so the silent switch no longer mutes it while Wingman is open.

**Added**
- Server logs for troubleshooting background delivery (no personal data): each sync logs how many reminders and which push service the device uses (or none); each tick with something due logs sent / failed / no-subscription counts; failed pushes log the push service's status code.

**Verified**
- `npm test` 58/58, typecheck and build clean.

## 2026-10-13 — Works with Vercel's "Redis" database too

**Added**
- The server now also accepts a plain `REDIS_URL` (what Vercel's **Redis** integration provides), not only Upstash's REST variables. Before, connecting "Redis" instead of "Upstash for Redis" left the server without storage: no reminders with the app closed and no sync.
- `server/urlRedisStore.ts`: same data layout as the Upstash store, over a normal Redis connection (reused between requests).

**Changed**
- Hosting guide: Step 0 no longer mentions the old `claude/wingman-designs` branch (everything is on `main`); Step 3 says either database works.

**Verified**
- `npm test` 58/58 (+2 real-Redis tests that run when `TEST_REDIS_URL` is set). Ran those against a local Redis 7.4: schedule → send once → re-sync keeps the sent copy → snooze → ack, and the vault compare-and-set (first real run of that Lua script). The API routes report `storage: true` and save/load the vault with `REDIS_URL` set. Build clean.

## 2026-10-11 — "Update available" bar

**Added**
- Each build has its own version id, also published as `/version.json` (never cached).
- The installed app checks for a newer version when it opens, when you come back to it, when you're back online, and every 30 minutes. If there is one, a bar says "A new version of Wingman is ready" / "גרסה חדשה של Wingman מוכנה" with **Refresh**; one tap loads it. Your data isn't touched.

**Verified**
- Browser run on the production build: no bar normally; after publishing a different `version.json` and returning to the app, the bar appeared; Refresh reloaded and the data was still there. `npm test` 58/58, build clean.

## 2026-10-11 — Main-planner features: yearly repeats, sync & backup, smarter planning, dark mode

**Repeats**
- New: **every year** (birthdays, anniversaries), **every month**, **weekdays (Mon–Fri)**. Feb 29 birthdays fall on Feb 28 in other years; "the 31st" falls on the last day of shorter months.
- Quick add understands "Mom's birthday Oct 20" (yearly, Family, heads-up at 9:00 on the day), "Pay rent every month on the 1st", "Standup weekdays at 9:30", "every year".
- Reminders gains a **Later** group, so a birthday months away is still listed.

**Backup & sync (#3)**
- **Download backup / Restore** in Settings (restore combines with what's there; works without the server).
- **Sync between devices**, end-to-end encrypted: Turn on sync → Share link (or type the code) on the other device. Newest change per item wins, deletions carry over, theme and push stay per device. Server route `api/vault` with compare-and-set versions.
- `npm run dev` now serves the API with in-memory storage, so sync can be tried locally.

**Smarter planning (#5)**
- **Focus timer**: open a task → Start focus timer → Done. Wingman records how long it really took.
- Quick add suggests your usual duration for a task it has seen before; Plan with Wingman uses learned durations, pads life areas that usually run over, and places tasks in the hours you usually get things done (overdue still goes first).
- Settings → **What Wingman has learned** (best hours, areas that run over) with Reset learning.

**Dark mode (#6)**
- Full dark theme; **Settings → Appearance: Auto / Light / Dark**. No flash of the wrong theme on launch.

**Verified**
- `npm test` 43/43 (new: repeats incl. leap years, parser cases, merge rules, encryption, backup files, vault versions, learning, planner preferences); typecheck and build clean.
- Browser run with two separate devices: device A turned on sync, device B opened the share link and received all data; a birthday added on B appeared on A; a deletion on A disappeared on B; focus timer started and finished; dark mode via phone setting and via Settings. No app errors (one expected 404: the first sync finding no existing copy).
- Not verified here: the Redis compare-and-set script on real Upstash (runs after deployment).

## 2026-10-11 — Notifications when the app is closed (Phase 3) + Vercel guide

**Added**
- Small server as Vercel functions (`api/`): `config`, `sync`, `tick`, `snooze`, `ack`, with logic in `server/` and Upstash Redis storage.
- The app keeps the server updated with the next 14 days of reminders, the morning brief and the evening recap (respecting quiet hours, push on/off and done items).
- Service worker shows server pushes even when Wingman is closed; alarms stay on screen until dismissed; a "Snooze 10 min" button works right from the notification.
- Optional email reminders through Resend; Settings has an email switch and address field.
- Settings shows the status of "When Wingman is closed" (checking / connect / on · synced).
- `vercel.json`, and `docs/HOSTING_VERCEL.md`, a step-by-step hosting tutorial (Vercel + Upstash + cron-job.org + optional Resend + iPhone install).

**Changed**
- If the app reopens after a reminder was due more than 10 minutes ago, it no longer rings or notifies late (the server already delivered it); the app tells the server about reminders it showed itself so you don't get them twice.

**Fixed during development**
- Copies of sent reminders (kept so Snooze works) would have been sent again a day later; they're now stored outside the schedule.

**Verified**
- `npm test` 29/29 (new: server delivery, stale/duplicate handling, snooze, dead subscriptions, email, API auth, real VAPID-signed + encrypted push request, schedule builder), typecheck and build clean, browser regression run with no console errors.
- Not verified here: delivery through a real phone's push service. That needs the deployed app (Step 8 of the guide tests it).
